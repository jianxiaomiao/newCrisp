# ECS 部署准备

首发拓扑为单实例 NewCrisp、同源 WebSocket 和独立 MySQL。Nexus 通过服务端接入凭据跳转和查询未读。实例内的 WebSocket 在线状态用于接单。多实例部署前须共享在线信息与通知。

## 构建和预发布

1. 使用 JDK 21 和项目锁文件构建。执行 `npm ci`、`mvn clean package`，记录 Git 提交和 `target/newcrisp-server.jar` 的 SHA-256。
2. 从备份恢复一份隔离的 MySQL 数据库并运行待发布 JAR。确认 Flyway 已成功应用 V7–V9，连同已有 V6。先验证已有 Nexus 会话和历史消息，再验证新建和旧数据读取。V8 的附件内容保存在 MySQL。备份、恢复和容量检查需要覆盖附件表。
3. 为预发布和正式站点分别设置 JDBC 连接、公开 HTTPS 来源、平台凭据摘要、Nexus 复核 URL 和密钥、JWT 私钥与 KID。配置项见项目 README。密钥从受限的环境文件或密钥服务注入。选择持久化工作目录与非 root 服务账户。
4. 将公开 HTTPS 域名代理到 NewCrisp 回环端口。WebSocket 位置转发 Upgrade 和 Connection，并使用 HTTP/1.1。空闲超时高于心跳周期。附件入口允许 6 MB 请求，应用限制单个文件 5 MB。访客页面的 CSP 由 NewCrisp 为每个站点生成，反向代理要保留该响应头。
5. 经过已经配置接入凭据的 Nexus 进入工作台，通过浏览器完成发消息、自动分配、附件、转派和结束。再用符合配置来源的站点验收 iframe、外部浏览器通知和访客接续。检查 Flyway、应用日志、分配队列和 MySQL 磁盘空间。

## 回滚演练

- 发布前保留当前 JAR、配置副本和数据库一致性备份，并记录恢复点。
- 在预发布验证用上一版 JAR 启动从迁移前备份恢复的新数据库。回滚需要使用与旧 JAR 兼容的数据库结构。
- 正式回滚先停止新的会话写入，保留故障时的库快照，再按已演练的恢复点切换。选定恢复点前核对新版本期间新增会话和附件的保留方案。
